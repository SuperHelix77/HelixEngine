# Sol internal execution transfer: offline boundary check

OBSERVED: the installed Engine can execute a scripted native internal tool call
once, deliver its actual result to the next local Codex request, and preserve
ordinary final-message transport. This is a loopback-mock transport check, not
a hosted Sol benchmark or capability/savings qualification.

## Failure and correction

The initial worker proof used Engine OFF. It established transport only and was
not accepted as an enabled candidate. A separate ON replay selected the generic
reducer for `unittest`. Its compact result retained exit 1 and the FAILED footer
but omitted `Ran 5 tests` and three `FAIL:` test identities. The next-request
assertion failed. Original stderr remained exactly recoverable.

The generic reducer now retains unittest trailer candidates and indexes literal
FAIL/ERROR section headers. Existing packet limits, omission counts, raw evidence,
and admission rules remain. Pytest and compiler behavior are unchanged.

The fixed ON replay passed both scripted cases:

| Case | Engine | Executions | Exit | Delivered representation |
| --- | --- | ---: | ---: | --- |
| Valid repair | ON | 1 | 0 | Raw: small-output bypass |
| Defective repair | ON | 1 | 1 | Raw: marginal-gain bypass |

The additional metadata makes this small failure packet uneconomic under the
existing admission heuristic. Raw delivery is the correct outcome. Root inspection
of the actual second request confirmed the test count and all four FAIL/ERROR
identities. This replay does **not** establish admitted compact-packet savings.
A separate real long-diagnostic unittest integration test exercises REDUCED
delivery, retaining counts, two failure references and exact archived stderr.

## Verification and accounting

- Fresh wheel, imported outside the checkout: **432 tests passed in 15.68 s**.
- Focused source tests: **13 passed**.
- Two scripted cases, two local provider requests each, one native internal
  command and one Engine execution each; no retries within either fixed case.
- No hosted inference, credentials, or genuine model-authored semantic decisions.
  Scripted final prose tests transport only.
- Independent finite oracle: valid artifact passed 735 graph cases, 16 invalid
  inputs and 751 nonmutation checks; defective artifact failed 732 assertions.
  Protected tests/settings and candidate bytes remained unchanged.
- Earlier OFF evidence, ON failure, and initial missing-source setup failure are
  retained separately. They are not erased from research cost/history.
- Native token savings, total economics and model-wide parity remain UNKNOWN.

## Remaining boundary

Correction from the next wire audit: the mock user input contained the task
description, not the three project files' contents. The scripted provider knew
the proposed repair independently. Preparing files on disk did not put those
files in model context. Automatic source preparation in an ordinary desktop
session remains unproven. The source write
is an ordinary native batch operation; only the subsequent tests ran through
Engine. This does not qualify transactional Engine publication, automatic session
interception, or a Sol release median. A new hosted pair is not justified merely
by this transport result.

Self-application remains conditional on observed net benefit and the relevant
capability/workflow gates. This correction prevents a known evidence omission;
it is not grounds to claim that the current agent became cheaper.
