# v0.2 integration gate

One integration adapter for every model: Codex lifecycle hook -> validated Engine request -> backend policy router -> native execution or exact Engine capture/reduction -> normal Codex continuation. Model-specific profiles are data behind that contract, never separate hook implementations.

The installed application executable is the acceptance target. A documentation claim, hook stdout, or rewritten command shown in the UI is insufficient. The offline acceptance receipt must identify the exact executable/version and show which command actually executed, exactly once, and which bytes reached the model-facing tool result. Preserve cwd, shell semantics, environment, stdin, exit status, permissions and interruption. Unsupported shapes retain original execution. Do not flatten interactive/background jobs into foreground execution.

A read-only rollout observer is telemetry only. Its counters begin at attachment, are per-response and deduplicated, and exclude unbound child threads. It is not a pre-inference gate. Hook trust must use the supported review flow; do not edit trust hashes or disable permission checks to make a probe pass.

A pre-inference gate must never classify ordinary user text as semantically resolved by a keyword heuristic. Skipping inference requires explicit authority, a bound state transition, idempotent committed completion, and no unresolved semantic obligations. Unexpected or ambiguous events go to the normal model. No replacement final answer is generated by the caller.

Order:

1. Offline installed-client interception proof and failure/recovery tests.
2. One opt-in shared integration, verified on actual desktop session events.
3. Native paired evidence of net savings, charging hook/startup/retrieval/testing overhead.
4. Strongest historical candidate audited against normal model-written final answers. Restore only final-answer path; charge any new model turn.
5. Capability/workflow parity gates and model-specific cohort medians. One graph per model; distinguish effort, cohort and excluded runs without multiplying integration patterns.
6. Publish v0.2 only with accurate tested coverage. Keep v0.1 release service/artifacts untouched.

No current claim of flawless execution, complete session/child coverage, universal savings or model-wide intelligence parity. The default preserves native semantics. Targets (65/65, 75/75, 90/90) are economic promotion gates after capability checks, not permission to suppress intelligence.

Official contract reviewed: https://learn.chatgpt.com/docs/hooks (2026-09-12). PreToolUse updatedInput is documented; installed execution behavior still requires proof.

Subagent acceptance: the same hook/Engine contract must cover parent and child tools. Bind child agent identity to authenticated native lifecycle events and actual child receipt sources; no model-name-only attribution. Count child and coordinator inference, retries and retrieval separately before summing research cost. Missing child counters remain unknown. Native completion events replace routine conversational polling. Do not lower effort, kill semantic work, or infer completion from a stopped status alone.
