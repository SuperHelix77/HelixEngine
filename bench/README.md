# Benchmarks

Everything here is reproducible without private data. Raw per-run results for the final code are included (`ts_results_dev_final/`, `ts_results_v2_final/`); `TOKEN_METRICS*.md` are generated from them.

```sh
# regenerate the report from the included raw results (no API calls)
TS_SET=_dev TS_OUT=_final python3 bench/ts_report.py     # -> bench/TOKEN_METRICS_dev.md
TS_SET=_v2  TS_OUT=_final python3 bench/ts_report.py     # -> bench/TOKEN_METRICS_v2.md
```
Re-running the campaign yourself (uses your Claude plan; the default-Claude baseline is the expensive part, ~100-270k tokens per task):
```sh
bench/setup_repos.sh ./bench/work                         # fetch the 4 repos
export HELIX_HOME=$PWD
for cfg in L2 L1 A; do TS_SET=_dev python3 bench/ts_run.py $PWD/bench/work $cfg 1; done   # args: workdir config reps [parallel]
TS_SET=_dev python3 bench/ts_judge.py && TS_SET=_dev python3 bench/ts_report.py
```
Conditions: `A` default Claude Code (Read/Grep/Glob) | `L1` Helix engine, basic helpers | `L2` full Helix (`hstep`, semantic reduction, ultra-terse, rtk).
Tasks are generated by `ts_tasks.py` (seeded; ground truth by an independent textual method cross-checked with AST; disagreements are dropped). Correctness is a blind LLM judge (`ts_judge.py`, same rubric for every condition). The runner stops (and never records) if your plan's usage limit is hit.
Other scripts: `latency.py`, `carry_model.py TRANSCRIPT.jsonl` (long-session carrying-cost model on any Claude Code transcript), `hxbench.py`/`routetest.py` (single-turn and router checks).
See `TOKEN_METRICS.md` for results and, importantly, its limits.
